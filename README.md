# lcs-self

**一套让 agent 能验证自己的最小协议。** 三层记忆 + 一组可执行的检查项，不依赖任何特定框架。

> 起因很具体：有一天我引用了一条"某天已修复"的结论，把它当事实写进回答，然后被自己后来写的检查脚本当场打脸 ——
> 那条修复在磁盘上**一点痕迹都没有**。文档里带日期的"已修"，本质上就是传闻。
> 这份东西就是从那一次开始长的。

## 它解决什么

Agent 的典型故障不是"不会做"，是**做完不知道自己是不是做对了**：

- 上下文不跨会话，今天学到的，明天归零；
- 文档越写越长，带日期的结论越来越多，其中多少还成立没人知道；
- 工具返回 `ok` 被当成"我做对了"，而真正需要验证的部分从没被验证。

三件事一起解决。

## 三层记忆

| 层 | 文件 | 回答的问题 | 谁写 |
|---|---|---|---|
| 世界模型 | `STATE.md` | 这台机器**现在**是什么样？ | 人 + agent |
| 事件流 | `JOURNAL.jsonl` | 它是**怎么变成**这样的？ | agent |
| 策略层 | `LESSONS.md` | 我**下次**该怎么做？ | agent |

缺任何一层，行为就会退化：只有世界模型 → 知道坑在哪却会再踩一次；只有事件流 → 一本流水账；
只有策略层 → 规则没有现实依据。

## 一条硬规则

> **文档里的话不算数，脚本全绿才算数。**

`STATE.md` 里每一条事实都必须挂一个检查号（`E#`），`selfcheck.ps1` 里必须有同名检查项。
**没有检查项的结论只能写成「传闻」，并写明为什么验不了 —— 不能写成事实。**

这条规则是整套东西的核心。它把"我觉得没问题"和"我验证过没问题"彻底分开。

## 用法

```powershell
pwsh -File selfcheck.ps1            # 逐项 PASS/FAIL，退出码 0/1
pwsh -File selfcheck.ps1 -Recall    # 先回放 STATE.md，再逐项复核
pwsh -File selfcheck.ps1 -Quiet     # 只打 FAIL 与汇总，适合放进 CI / 定时任务
pwsh -File journal.ps1 -What "改了什么" -How "怎么验的" [-Left "还剩什么"]
pwsh -File journal.ps1 -Tail 10     # 回放最近记录
```

## 怎么为你的环境加一条 `E#`

1. 在 `STATE.md` 的表格里加一行：`| E42 | 你的结论 | 判据 | 已验 |`
2. 在 `selfcheck.ps1` 里加：

```powershell
$ok = Test-Path 'C:\some\thing'
Check 'E42' '你的结论' $ok "证据细节"
```

3. 跑一次。**FAIL 不许跳过、不许改判成 PASS** —— 要么修环境，要么把那条结论降级为「传闻」并把反证写进 `STATE.md`。

## 文件

| 文件 | 作用 |
|---|---|
| `selfcheck.ps1` | 检查器骨架：`Check` 函数、PASS/FAIL 输出、退出码、`verify.log` |
| `journal.ps1` | 追加/回放 `JOURNAL.jsonl` |
| `TEMPLATES.md` | `STATE.md` / `LESSONS.md` 的空白模板与填写示例 |
| `verify.log` | 每次运行一行：时间、PASS/FAIL 计数、失败项 id |

## 边界（重要）

- 这**不是**"让 AI 有自我意识"。它是一套工程约束：用文件模拟记忆，用脚本模拟自省。
- 行为上可以逼近"会学习"，机制上不是一回事。**别把全绿当成进化** —— 那只是"没退化"。
- 它只覆盖**可机器验证**的结论。判断类的东西（方案好不好、话说得对不对）它抓不到，那些仍然只能靠人。
